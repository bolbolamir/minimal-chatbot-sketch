# دستیار بیمه: نسخه قابل اجرا

یک نمونه کوچک برای سؤال عمومی و خرید بیمه خودرو، بدون LLM در زمان اجرا و بدون وابستگی خارجی. ورودی‌ها متن آزاد فارسی هستند؛ خروجی مدل از روی پیام واقعی محاسبه می‌شود و پاسخ‌های مکالمه از قبل بازپخش نمی‌شوند.

## اجرا

```bash
python3 main.py --demo
python3 main.py --demo --trace
python3 main.py --trace
```

پایتون ۳.۱۳ یا بالاتر لازم است. اگر محیط مجازی پوشه فعال نیست، می‌توانید به جای `python3` از `.venv/bin/python` استفاده کنید. در حالت تعاملی برای خروج `exit` بنویسید.

گزینه `--demo` پنج پیام نمونه را از همان مسیر پردازش واقعی عبور می‌دهد. گزینه `--trace` بعد از هر نوبت، تمام خروجی فهم پیام، اقدام انتخاب‌شده و وضعیت مکالمه را به صورت JSON نشان می‌دهد.

## اجرا با Docker

از پوشه پروژه ایمیج را بسازید:

```bash
docker build -t insurance-assistant .
```

اجرای تعاملی همراه با نمایش متغیرها:

```bash
docker run --rm -it insurance-assistant --trace
```

اجرای مکالمه نمونه بدون ورودی تعاملی:

```bash
docker run --rm insurance-assistant --demo
docker run --rm insurance-assistant --demo --trace
```

برای خروج از گفت‌وگو `exit` بنویسید. آرگومان‌های بعد از نام ایمیج مستقیماً به `main.py` داده می‌شوند. کانتینر با پایتون ۳.۱۴ و کاربر غیر root اجرا می‌شود. فقط فایل‌های برنامه وارد ایمیج می‌شوند؛ محیط مجازی و فایل‌های محلی کپی نمی‌شوند. این برنامه CLI است؛ پورت یا سرویس جانبی نیاز ندارد. وضعیت مکالمه فقط در حافظه همان اجرا باقی می‌ماند.

## مکالمه قابل اجرا

```text
کاربر: سلام
دستیار: سلام! ...

کاربر: برای پژو ۲۰۶ مدل ۱۴۰۰ بیمه میخوام ارزون باشه
دستیار: نوع سوخت خودرو چیست؟

کاربر: فرانشیز یعنی چی؟
دستیار: [پاسخ بازیابی‌شده از FAQ نمونه]

کاربر: ماشینم بنزینیه
دستیار: [دو پیشنهاد نمونه، با قیمت و خلاصه پوشش]

کاربر: همون شرکت الف رو ادامه بده
دستیار: [لینک نمایشی ادامه خرید]
```

می‌توانید مشخصات را جداگانه هم وارد کنید: ابتدا درخواست خرید، سپس `۱۴۰۰`، سپس `پژو ۲۰۶` و سپس `بنزینی`.

## جریان داده

```text
text + Conversation
       |
       v
ExampleUnderstanding
  TF-IDF character vectors + nearest labeled intent
  + small vehicle slot parser
       |
       v
Understanding
  intents / car_updates / preferences / question / selected_offer_id
       |
       v
Assistant updates Conversation
  car / buying / preferences / current offers
       |
       v
ExamplePolicy
  nearest labeled state -> Action
       |
       +-- greet / ask / clarify -> approved wording
       +-- answer -> ExampleFAQ -> retrieved answer
       +-- compare -> required car fields -> ExampleInsurance -> offers
       +-- checkout -> current selected offer -> demo checkout URL
       |
       v
Turn(meaning, action, response) + last 8 messages in history
```

## فایل‌ها

| فایل | مسئولیت |
|---|---|
| `main.py` | اتصال وابستگی‌ها، اجرای تعاملی، نمونه مکالمه و نمایش متغیرها |
| `domain.py` | قرارداد داده‌ها: خودرو، مکالمه، تشخیص، اقدام، پیشنهاد و نتیجه نوبت |
| `data.py` | مثال‌های برچسب‌خورده intent و سیاست و محتوای FAQ نمونه |
| `models.py` | بردارسازی متن، تشخیص intent، استخراج مشخصات و سیاست نزدیک‌ترین همسایه |
| `services.py` | رابط سرویس‌ها به همراه پیاده‌سازی نمایشی FAQ و بیمه |
| `rendering.py` | سؤال‌های ثابت و نمایش اطلاعات پیشنهادها |
| `assistant.py` | اتصال مراحل و اجرای هر نوبت مکالمه |

## چه چیزی از داده یاد گرفته می‌شود؟

تشخیص intent از نزدیک‌ترین مثال برچسب‌خورده به بردار پیام انجام می‌شود. سیاست، نزدیک‌ترین وضعیت برچسب‌خورده را بر اساس intent، فعال‌بودن خرید و اولین مشخصه ناقص پیدا می‌کند و اقدام آن را برمی‌گرداند. مثال‌ها در `data.py` قرار دارند و در شروع برنامه index می‌شوند؛ فایل وزن یا پایگاه داده ساخته نمی‌شود.

این یک baseline کلاسیک مبتنی بر TF-IDF و نزدیک‌ترین همسایه است، نه embedding عصبی fine-tune شده. استخراج مشخصات فعلاً با یک parser کوچک انجام می‌شود؛ بنابراین کل سیستم rule-based نیست، ولی استخراج موجودیت هم هنوز مدل آموزش‌دیده نیست. رابط‌ها اجازه می‌دهند بعداً طبقه‌بند و استخراج‌کننده آموزش‌دیده جایگزین شوند.

## رفتار وضعیت

- سه مشخصه سال ساخت، مدل و سوخت قبل از مقایسه الزامی‌اند.
- سؤال FAQ وضعیت خرید و اطلاعات خودرو را حفظ می‌کند.
- اصلاح مشخصات یا ترجیحات، پیشنهادهای قبلی را پاک می‌کند و مقایسه جدید انجام می‌شود.
- پیشنهاد انتخابی باید در نتایج فعلی موجود باشد؛ اشاره مبهم به چند شرکت لینک خرید تولید نمی‌کند.
- پاسخ نامطمئن بدون اعمال مشخصات استخراج‌شده به کاربر برگردانده می‌شود.
- اطلاعات ساختاریافته مستقل از تاریخچه محدود متن است. هیچ ذخیره‌سازی دائمی اضافه نشده است.

## محدودیت‌های روشن

این نمونه برای نمایش معماری است و ارزیابی تولیدی ندارد. شباهت‌ها احتمال کالیبره‌شده نیستند و آستانه‌ها نمونه‌اند. تشخیص intent فعلاً یک برچسب دارد و جمله‌های چندمنظوره، نفی و اشاره‌های پیچیده را کامل پوشش نمی‌دهد. مدل سیاست فعلاً فقط از خلاصه وضعیت استفاده می‌کند؛ مدل تولیدی می‌تواند تاریخچه محدود را هم مصرف کند.

کاتالوگ کوچک شامل پژو ۲۰۶، پژو ۲۰۷ و پراید است. parser سال شمسی می‌خواند؛ سرویس نمایشی بازه ۱۳۰۰ تا ۱۴۰۵ را می‌پذیرد. واژگان سوخت شامل بنزین، گازوئیل، دوگانه و برقی است.

تمام FAQها، پوشش‌ها و قیمت‌ها نمایشی‌اند. قیمت از یک فرمول ساختگی محاسبه می‌شود و اعتبار بیمه‌ای ندارد. لینک خرید واقعی نیست و هیچ پرداخت یا صدوری انجام نمی‌شود. برای استفاده واقعی باید `InsuranceService` به سرویس بیمه متصل شود؛ نوع بیمه، مشخصات تکمیلی، اعتبار پیشنهاد و رضایت خرید در همان سرویس بررسی می‌شوند.
